# Django + React starter

A barebones Django project with one custom app, `client`, containing a React
frontend. Django uses SQLite and includes its standard admin and authentication
apps. The frontend is a single welcome page, ready for your own components.

For container development with hot reload and production image builds, see
[Docker workflows](docker/README.md).

## Requirements

- Python 3.12–3.14
- Node.js 22.12+ and npm (Node 22 is selected by `.nvmrc`)

Versions selected on September 14, 2026: Django 6.1.1, React 19.3.0, and Vite 8.3.0.
See the [Django releases](https://www.djangoproject.com/download/),
[React versions](https://react.dev/versions), and
[Vite releases](https://vite.dev/releases).

## Quick start

From this directory:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
npm --prefix client ci
npm --prefix client run build
python manage.py migrate
python manage.py runserver
```

Open <http://127.0.0.1:8000/>. Django serves the generated React HTML and, in
development, its static assets. Build the frontend before opening this URL;
otherwise Django cannot find `client/dist/index.html`.

For the optional admin interface, run `python manage.py createsuperuser` and open
<http://127.0.0.1:8000/admin/>.

## Frontend development

Keep Django running on port 8000 and start Vite in another terminal:

```sh
npm --prefix client run dev
```

Open <http://127.0.0.1:5173/> for React Fast Refresh. Edit `client/src/App.jsx` to
start building your UI. Vite proxies `/api`, `/admin`, and `/static/admin` to
Django. No API endpoints or frontend router are included yet.

Vite serves the source directly during development. Run
`npm --prefix client run build` again to update the version served by Django.
If you started Django before the first build, restart it so it discovers the
generated static directory.

To preview the frontend build:

```sh
npm --prefix client run preview
```

Open <http://127.0.0.1:4173/static/client/>. Django must also be running to use
the proxied backend routes.

The layout follows `vcelnice-django`: root management/build files, split settings,
and a Django `client` app that owns the frontend source and build. All starter
code is generic; no business models, content, assets, credentials, or deployment
configuration were copied.

## Checks

With the virtual environment activated:

```sh
python manage.py check
python manage.py test --settings=config.settings.testing
python manage.py makemigrations --check --dry-run
npm --prefix client run build
```

## Build and deployment

`./build.sh` installs frontend dependencies from the lockfile, builds React, and
runs `collectstatic`. Activate the Python virtual environment and install
`requirements.txt` first. Set `PYTHON` if you need to select another interpreter.

Vite generates asset URLs under `/static/client/`. Django collects those files
and admin assets into `staticfiles/`. Retain `client/dist/index.html` in your
deployment because Django renders it for `/`.

Management commands default to `config.settings.development`. WSGI and ASGI
default to `config.settings.production`, which requires environment variables:

```sh
export DJANGO_SETTINGS_MODULE=config.settings.production
export DJANGO_SECRET_KEY="$(python -c 'import secrets; print(secrets.token_urlsafe(64))')"
export DJANGO_ALLOWED_HOSTS=your-domain.example
# Optional: comma-separated trusted origins for cross-origin CSRF requests.
export DJANGO_CSRF_TRUSTED_ORIGINS=https://your-domain.example
python manage.py check --deploy
./build.sh
python manage.py migrate
```

Keep the generated secret stable in your deployment's secret store. Settings read
the process environment directly; `.env` files are not loaded automatically.

Production requires HTTPS and secure cookies. Deploy with a WSGI/ASGI server
pointing to `config.wsgi:application` or `config.asgi:application`, and configure
your web server to serve `/static/` from `staticfiles/`. If a trusted proxy
terminates HTTPS, configure Django's `SECURE_PROXY_SSL_HEADER` to match that
proxy before enabling traffic. HSTS starts at one hour; subdomain coverage and
preloading are left for your deployment to decide.

SQLite is the starter database. Provide persistent storage for it or configure a
database appropriate for your deployment. Set `DJANGO_DATABASE_PATH` to change
its file location. The optional [Docker workflow](docker/README.md) packages
Gunicorn and WhiteNoise for hosting and configures persistent database storage.
